Verify your download

An APK from a website is just a file — nothing about downloading it proves who built it. Two checks fix that, and they're independent: one you run yourself before installing, one Android runs for you forever after.

The signing key
Start with the fingerprint

Everything below only means something if this is the right key. Compare it character by character.

PUBLISH_FINGERPRINT_HERE

Check this against a source that isn't this page. Anyone able to serve you a fake APK from thrilla.me can serve a fake key and a fake fingerprint right beside it — the whole check would then pass, and prove nothing. The same fingerprint is published on GitHub, X and Telegram. If they don't all agree, stop and tell us.

This is the honest limit of any download-page verification: it detects a tampered file, not a compromised publisher. A second source is what closes the gap.

What you'll need. GnuPG and a terminal. On Debian or Ubuntu apt install gnupg, on macOS brew install gnupg, on Windows Gpg4win (its commands are the same in PowerShell). Verifying on a computer is the point — a phone can download the APK, but it can't easily check it.

GPG
Three commands

We sign one SHA256SUMS file that covers every build, then you check your APK against it — the same layout Bitcoin Core and Tor use.

1 Import the key

Download thrilla-signing-key.asc, then import it and print its fingerprint to compare with the one above.

gpg --import thrilla-signing-key.asc gpg --fingerprint thrilla

Do the comparison by eye, across all forty characters. A key that differs in the middle is the whole attack.

2 Check the signature on the checksums

Put SHA256SUMS and SHA256SUMS.asc in the folder you downloaded the APK into.

gpg --verify SHA256SUMS.asc SHA256SUMS

You're looking for one line — Good signature — and the fingerprint at the bottom matching step 1:

gpg: Signature made Tue 01 Sep 2026 10:05:22 UTC gpg: using EDDSA key 4772DA8C5DF761429F0BCD454D21817AA0EBF64E gpg: Good signature from "Thrilla <…>" [unknown] gpg: WARNING: The key's User ID is not certified with a trusted signature! gpg: There is no indication that the signature belongs to the owner. Primary key fingerprint: 4772 DA8C 5DF7 6142 9F0B CD45 4D21 817A A0EB F64E

That WARNING is normal and expected. It is not saying the signature is bad — it says you haven't told GPG you personally trust this key, which you haven't and don't need to. "Good signature" plus a fingerprint that matches is the result you want. If you'd rather not see it again, sign the key locally with gpg --lsign-key.

3 Check the APK against the checksums

Now that the sums are proven authentic, confirm your file matches one.

# Linux sha256sum --ignore-missing -c SHA256SUMS # macOS, or anywhere without --ignore-missing grep ' thrilla.apk$' SHA256SUMS | shasum -a 256 -c - # Windows PowerShell — compare this against the line in SHA256SUMS Get-FileHash thrilla.apk -Algorithm SHA256
thrilla.apk: OK

--ignore-missing matters: SHA256SUMS lists both the mainnet and Signet builds, and without it the check fails on whichever one you didn't download.

If any step fails, don't install it. FAILED from step 3, or anything other than "Good signature" in step 2, means the file you have is not the file we signed. Delete it, download again on a different network, and check once more.

If it fails a second time, get in touch before installing anything — that's worth knowing about quickly.

Android
The check that keeps running

The APK carries its own signature, and Android enforces it on every update — including for people who never verify anything by hand.

Once Thrilla is installed, Android will refuse any update signed by a different key. A fake build can't replace a real one on your phone; it can only ever fool a fresh install. That makes the very first install the moment worth checking — which is exactly what the GPG steps above are for.

Reading the certificate yourself (optional, needs the Android SDK build-tools):

apksigner verify --print-certs thrilla.apk | grep -i 'SHA-256 digest'

The fingerprint it prints is published with each release on the releases page. It is a separate value from the GPG fingerprint above and the two are not interchangeable — one identifies the app to your phone, the other identifies the download to you.

Heads up Reinstalling with a different signing key means uninstalling first — and uninstalling takes this device's keys with it. Have your recovery phrase before you do that.
